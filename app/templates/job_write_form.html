Off by default. Read-back verification re-reads every file immediately after writing it and compares checksums, which is the safest way to catch a bad write — but on real tape hardware it forces the drive to switch between write and read mode for every single file. On sources with many small files this can make the job 10–20x slower (observed: small-file items dropped from ~15–20s each to sub-second once this was turned off). Recommended: leave it off here and run a separate Verify job afterward instead.

The job runs in the background: scan → allocate tapes → copy → SHA256 (→ read-back verify, if enabled above) → catalog. It is idempotent; re-running after an interruption skips already-written units.
